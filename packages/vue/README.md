# @offline-agency/image-puzzle-vue

Vue 3 component and composable for game definitions generated by the PHP
package
[`offline-agency/image-puzzle`](https://github.com/offline-agency/php-image-puzzle).
They mount the shared
[`@offline-agency/image-puzzle-player`](../player/README.md), so every mode
(sliding, swap, rotation, strips, jigsaw) plays under the same rules, input and
accessibility as the Web Component and the Livewire player.

```sh
npm install @offline-agency/image-puzzle-vue
```

The only peer dependency is `vue` (`^3.5.0`). The player and engine are
installed with this package.

## Component

```vue
<script setup lang="ts">
import { ref } from 'vue';
import { ImagePuzzlePlayer } from '@offline-agency/image-puzzle-vue';
import type { ImagePuzzlePlayerHandle } from '@offline-agency/image-puzzle-vue';

const props = defineProps<{ saved: object | null }>();
const puzzle = ref<ImagePuzzlePlayerHandle | null>(null);
</script>

<template>
  <ImagePuzzlePlayer
    ref="puzzle"
    src="/puzzles/jigsaw.json"
    :initial-state="props.saved"
    locale="it"
    @complete="({ moves, elapsedMs }) => submit(moves, elapsedMs)"
    @error="({ code }) => report(code)"
  />
</template>
```

| Prop | Applied | Notes |
| --- | --- | --- |
| `definition` | on change | Definition object. Wins over `src`. Compared by identity: keep it in a `shallowRef` or `computed` |
| `src` | on change | Definition URL. A newer source cancels a pending load |
| `initialState` | first load after mount | Saved state (`exportState()`). Later sources start fresh games; `null` means a fresh game |
| `baseUrl`, `locale`, `messages` | on change | Labels update without restarting the game |
| `theme`, `themeClass` | on change | See Styling in [PLAYER_API.md](../../docs/PLAYER_API.md#styling) |
| `controls` (default `true`), `persist` (default `false`), `motion`, `pauseWhenHidden` (default `true`), `fetch`, `clock`, `randomSeed`, `onListenerError` | on mount | Change the component `key` to remount with new values |

Events: `ready`, `move`, `state-change`, `progress`, `complete` and `error`.
The payloads are the typed engine payloads (`PlayerEventMap`) and are
validated by the component's `emits` declaration.

A template ref exposes `player`, `load(source, options?)`, `reset()`,
`shuffle(seed?)`, `exportState()` and `importState(state)`. The methods throw
while the player is not mounted.

### Ownership

The game state lives in the player: the component is *uncontrolled*. Read
progress from the events or `exportState()`, and restore it with
`initialState` on a new mount (a new `key`), `load(source, { state })` or
`importState(state)`. Passing a new `initialState` to a mounted component does
nothing, so a save never loops back into the game that produced it.

## Composable

```ts
import { ref } from 'vue';
import { useImagePuzzlePlayer } from '@offline-agency/image-puzzle-vue';

const target = ref<HTMLElement | null>(null);
const { player } = useImagePuzzlePlayer(target, () => ({ src: source.value, locale: locale.value }), {
  move: ({ action }) => track(action),
});
```

`options` and `handlers` accept a value, a ref or a getter. The composable
creates the player when the component mounts, applies option changes and
destroys it before unmount. `player` is a shallow ref (`null` before mount and
on the server).

## Lifecycle

- **Unmount** destroys the player, its DOM and its listeners.
- **SSR**: server rendering outputs the empty container only. The player is
  created in `onMounted`, so nothing touches the DOM on the server.
- Several components on one page are independent.

## Using the Web Component from Vue

Tell the template compiler that `image-puzzle-*` tags are custom elements,
then register the element once:

```ts
// vite.config.ts
import vue from '@vitejs/plugin-vue';

export default {
  plugins: [vue({ template: { compilerOptions: { isCustomElement: (tag) => tag.startsWith('image-puzzle-') } } })],
};
```

With the runtime template compiler, set
`app.config.compilerOptions.isCustomElement` to the same function instead.

```vue
<script setup lang="ts">
import '@offline-agency/image-puzzle-player/define';
</script>

<template>
  <image-puzzle-player :definition="definition" locale="it" @puzzle-complete="(event) => submit(event.detail.moves)" />
</template>
```

Vue assigns a binding to the element property when the element has one, so
`definition` and `state` objects are not serialised into attributes.
`@puzzle-*` listeners receive the `CustomEvent`; the payload is
`event.detail`. The element keeps its own lifecycle (a DOM move keeps the
game; see [Web Component](../../docs/PLAYER_API.md#web-component)). Prefer
`<ImagePuzzlePlayer>` for typed events and the template ref handle.

The full player API is in [docs/PLAYER_API.md](../../docs/PLAYER_API.md).
