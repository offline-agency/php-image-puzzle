# @offline-agency/image-puzzle-react

React 19 component and hook for game definitions generated by the PHP package
[`offline-agency/image-puzzle`](https://github.com/offline-agency/php-image-puzzle).
They mount the shared
[`@offline-agency/image-puzzle-player`](../player/README.md), so every mode
(sliding, swap, rotation, strips, jigsaw) plays under the same rules, input and
accessibility as the Web Component and the Livewire player.

```sh
npm install @offline-agency/image-puzzle-react
```

The only peer dependency is `react` (`^19.0.0`). The player and engine are
installed with this package.

## Component

```tsx
import { ImagePuzzlePlayer } from '@offline-agency/image-puzzle-react';
import type { ImagePuzzlePlayerHandle } from '@offline-agency/image-puzzle-react';

function Puzzle({ saved }: { saved: object | null }) {
  const handle = useRef<ImagePuzzlePlayerHandle>(null);
  return (
    <ImagePuzzlePlayer
      ref={handle}
      src="/puzzles/jigsaw.json"
      initialState={saved}
      locale="it"
      className="puzzle"
      onComplete={({ moves, elapsedMs }) => submit(moves, elapsedMs)}
      onError={({ code }) => report(code)}
    />
  );
}
```

| Prop | Applied | Notes |
| --- | --- | --- |
| `definition` | on change | Definition object. Wins over `src`. Compared by identity: memoise it |
| `src` | on change | Definition URL. A newer source cancels a pending load |
| `initialState` | first load after mount | Saved state (`exportState()`). Later sources start fresh games; `null` means a fresh game |
| `baseUrl`, `locale`, `messages` | on change | Labels update without restarting the game |
| `theme`, `themeClass` | on change | See Styling in [PLAYER_API.md](../../docs/PLAYER_API.md#styling) |
| `controls`, `persist`, `motion`, `pauseWhenHidden`, `fetch`, `clock`, `randomSeed`, `onListenerError` | on mount | Change the component `key` to remount with new values |
| `id`, `className`, `style` | on change | Passed to the container `<div>` |
| `onReady`, `onMove`, `onStateChange`, `onProgress`, `onComplete`, `onError` | always the newest | Payloads are the typed engine payloads (`PlayerEventMap`) |

The `ref` handle exposes `player`, `load(source, options?)`, `reset()`,
`shuffle(seed?)`, `exportState()` and `importState(state)`. The methods throw
while the player is not mounted.

### Ownership

The game state lives in the player: the component is *uncontrolled*. Read
progress from the callbacks or `exportState()`, and restore it with
`initialState` on a new mount (a new `key`), `handle.load(source, { state })`
or `handle.importState(state)`. Passing a new `initialState` to a mounted
component does nothing, so a save never loops back into the game that
produced it.

## Hook

```tsx
import { useImagePuzzlePlayer } from '@offline-agency/image-puzzle-react';

function Board() {
  const { ref, player } = useImagePuzzlePlayer<HTMLElement>({ src: '/puzzles/swap.json', onMove: ({ action }) => track(action) });
  return <section ref={ref} aria-busy={player === null} />;
}
```

It takes the same options and callbacks as the component and returns the
container `ref` and the live `player` (`null` before mount and on the server).

## Lifecycle

- **Strict Mode**: the development setup/cleanup/setup cycle creates no
  duplicate player and fires no duplicate events. The source is loaded only by
  the mounted instance.
- **Unmount** destroys the player, its DOM and its listeners.
- **SSR**: server rendering outputs the empty container only. The player is
  created in an effect, so nothing touches the DOM on the server.
- Several components on one page are independent.

## Using the Web Component from React

React 19 supports custom elements: it assigns a prop to the element property
when the element has one (so `definition` and `state` objects are not
serialised into attributes), sets other props as attributes, and turns
`on<event-name>` props into listeners for that exact event name. Register the
element once, then use it like any tag:

```tsx
import '@offline-agency/image-puzzle-player/define';

<image-puzzle-player definition={definition} locale="it" onpuzzle-complete={(event) => submit(event.detail.moves)} />;
```

TypeScript needs a declaration of the tag:

```ts
import type { ImagePuzzlePlayerElement, PlayerEventMap } from '@offline-agency/image-puzzle-player';
import type { DetailedHTMLProps, HTMLAttributes } from 'react';

declare module 'react' {
  namespace JSX {
    interface IntrinsicElements {
      'image-puzzle-player': DetailedHTMLProps<HTMLAttributes<ImagePuzzlePlayerElement>, ImagePuzzlePlayerElement> & {
        src?: string;
        locale?: string;
        definition?: object | null;
        state?: object | null;
        'onpuzzle-ready'?: (event: CustomEvent<PlayerEventMap['ready']>) => void;
        'onpuzzle-complete'?: (event: CustomEvent<PlayerEventMap['complete']>) => void;
        'onpuzzle-error'?: (event: CustomEvent<PlayerEventMap['error']>) => void;
      };
    }
  }
}
```

The element keeps its own lifecycle (a DOM move keeps the game; see
[Web Component](../../docs/PLAYER_API.md#web-component)). Prefer
`<ImagePuzzlePlayer>` for typed callbacks and the ref handle.

The full player API is in [docs/PLAYER_API.md](../../docs/PLAYER_API.md).
